# Brisk 1.7.1

### New

- **Updates are checked against the signature, not just a checksum.** Brisk
  already verified the sha256 of anything it downloaded — but that checksum
  comes from the same file that names the download. Anyone able to serve a
  different manifest could serve a matching checksum with it. Brisk now also
  requires that the installer is signed, that Windows trusts the chain, and
  that the certificate carries the name of the person who builds Brisk.
  Anything else is deleted without being run.

### Changed

- **No more gap at startup.** The loading window used to close, and then the
  main window took a moment to appear — on a cold machine, several seconds of
  nothing. The main window is now built while the loading window is still on
  screen, which is what it was there for. The work itself cannot be made
  faster; it is the cost of running code for the first time.

- **Driver updates are logged one by one**, with the name of each driver and
  whether it succeeded. If something stops working after a driver update — a
  camera, a microphone, a screen — the log now says exactly what changed.
  Before it only said how many.

  Worth knowing either way: Brisk does not download drivers itself. It asks
  Windows Update, the same way Windows does, and installs only what finished
  downloading. An interrupted download is never installed. But a driver that
  installs successfully can still be worse than the one it replaced, and that
  is Windows Update's judgement, not Brisk's. Device Manager → the device →
  Driver → **Roll Back Driver** undoes it.

### Fixed

- `Brisk.exe` is a separate download again. It was missing from the 1.7.0
  release by mistake.
